# Progress on agent-deck-app/alpha#1

What each item's work learned, in the order it was worked.

- #2: Added `src/index.ts` with the optional `ProbeReport` sections, section report aliases, detector contracts, and an async `probe()` that currently returns `{}`. Added a public empty-directory test in `src/index.test.ts`. `pnpm test` and `pnpm typecheck` pass. No unresolved issues.
- #3: Added `src/fixtures.ts` with `withRepo`, using a temporary directory, recursive parent creation, formatted JSON for object values, and `finally` cleanup that preserves callback errors. Added public helper tests in `src/fixtures.test.ts` for materialization, nested paths, JSON values, and thrown callbacks. An initial top-level-only write failed the nested-path test; recursive `mkdir` fixed it. `pnpm test` and `pnpm typecheck` pass. No unresolved issues.
- #4: Added `src/detect/node.ts` and re-exported `detectNodeVersion` plus its report types from `src/index.ts`. It reads both Node version files, gives `.nvmrc` precedence among readable values, records each seen file and its value/status, accepts numeric, `v`-prefixed, LTS, and common alias selectors, and returns null only when both files are absent. Empty/unparseable or otherwise unreadable files remain reported as unreadable. Added fixture-backed public tests; an initial missing-file check exposed that absent reads were being marked seen, fixed by marking presence only after a successful read or non-ENOENT error. `pnpm test` and `pnpm typecheck` pass. No unresolved issues.
- #5: Added `src/detect/tool-versions.ts` and re-exported `detectToolVersions` plus its report types from `src/index.ts`. It returns null when `.tool-versions` is absent and otherwise reports the source plus every tool's first whitespace-delimited version, including unrecognised tools; blank and `#` comment content is ignored. Added fixture-backed tests covering absence, empty files, comments, fallback versions, and unknown tools. The initial missing-export test failed as expected; the comment test then exposed comment text being parsed as a tool and drove the comment filtering. `pnpm test` and `pnpm typecheck` pass. No unresolved issues.
- #6: Added the targeted `.mise.toml` detector in `src/detect/mise.ts`, with ordered support for `.mise.toml`, `mise.toml`, and `.config/mise/config.toml`. It reports scalar versions, array fallbacks, inline-table `version` values, multiline arrays, quoted hashes, and ignores non-`[tools]` tables; malformed supported entries and headers throw the public `MiseTomlSyntaxError` with a line number. Added fixture-backed public tests and re-exported the detector, report types, filename type, and syntax error from `src/index.ts`. A small regex parser was insufficient for valid TOML constructs, so the implementation uses a targeted stateful parser without adding a dependency. `pnpm test` and `pnpm typecheck` pass. No unresolved issues.
- #7: Added `detectPythonRubyVersions` in `src/detect/python-ruby.ts`, returning ordered Python version lists, a Ruby version, and readable/unreadable file reports while distinguishing absent files. Factored shared blank/comment/whitespace line parsing into `src/detect/version-file.ts` and updated the Node detector to use it. Added fixture-backed public tests and re-exported the detector and report types from `src/index.ts`. `pnpm test` and `pnpm typecheck` pass. No unresolved issues.
- #8: Added `detectGoMod` in `src/detect/go-mod.ts`, re-exported with its report types from `src/index.ts`. It returns separate labelled `go` language-floor and `toolchain` pin values, preserves `go.mod` as the source, distinguishes absent from present-without-directives, handles line comments/whitespace, and skips `require` blocks. The initial early-return parser dropped the second directive and then parsed fake directives in `require`; tests drove collecting both values and tracking block state. Added fixture-backed public tests. `pnpm test` and `pnpm typecheck` pass. No unresolved issues.
- #9: Added `detectPackageJson` in `src/detect/package-json.ts` and re-exported it with its report types. It returns null for an absent manifest, reports the package manager name/version with Corepack `+sha...` integrity suffixes removed, preserves `engines.node` as a raw range, and reports JSON parse messages instead of throwing. Added fixture-backed public tests for absence, manager parsing, suffix stripping, engine ranges, and malformed JSON. `pnpm test` and `pnpm typecheck` pass. No unresolved issues.
- #10: Added `detectPackageManager` in `src/detect/package-manager.ts` and re-exported its detector and report types. It maps the four supported lockfiles to `pnpm`, `npm`, `yarn`, and `bun` with their frozen install commands, lists all lockfiles and marks unresolved multi-lockfile results as ambiguous, uses a valid `packageManager` declaration to resolve a tie, and reports a manifest-only repository rather than returning null. Added fixture-backed tests for each mapping, ambiguity, tie-breaking, manifest-only state, and incomplete declarations. The initial first-match implementation failed the multi-lockfile test and was changed to collect candidates before resolving. `pnpm test` and `pnpm typecheck` pass. No unresolved issues.
- #11: Added `detectPythonPackageManager` in `src/detect/python-package-manager.ts` and re-exported it with its report types from `src/index.ts`. It maps `uv.lock`, `poetry.lock`, `Pipfile.lock`, and `requirements.txt` to their install commands, records `pyproject.toml` build-backend and tool evidence, uses `[tool.uv]`/`[tool.poetry]` to corroborate or resolve lockfile ties, and reports unresolved conflicts as ambiguous. A pyproject-only repository remains meaningful and falls back to pip input when no more specific manager is identified. Added fixture-backed tests for mappings, corroboration, ambiguity, nested tool tables, and quoted `#` values. The targeted parser avoids a runtime dependency; `uv.lock` uses `uv sync` rather than a frozen variant. `pnpm vitest run src/detect/python-package-manager.test.ts --reporter=verbose`, `pnpm test`, and `pnpm typecheck` pass. No unresolved issues.
- #13: Added `detectDevContainer` in `src/detect/devcontainer.ts` and exported it with `DevContainerFileName`/`DevContainerReport` from `src/index.ts`. It prefers `.devcontainer/devcontainer.json`, falls back to root `.devcontainer.json`, reports the selected source and `kind: "declaration"`, preserves `image`, `features`, `postCreateCommand`, and `remoteUser`, and returns parse errors for present malformed files. A targeted JSONC normalizer was needed after direct `JSON.parse` failed the comment/trailing-comma test; it handles line/block comments without touching strings and trailing commas without a runtime dependency. Fixture-backed public tests cover absence, both paths, precedence, all named fields, JSONC, and malformed input. `pnpm test` and `pnpm typecheck` pass. No unresolved issues.
- #14: Added `detectPackageScripts` in `src/detect/package-scripts.ts` and re-exported it with its report types. It reads package.json scripts, preserves every string-valued script, exposes the recognised test/test:unit/typecheck/lint/build entries as package-manager commands, detects the manager from supported lockfiles (using a valid declaration to resolve ties or a manifest-only repo), and omits npm's generated placeholder test from recognised commands while retaining it as evidence. Malformed manifests report an error without an empty scripts result. Added fixture-backed public tests for recognised commands, custom scripts, placeholder filtering, npm run syntax, declaration fallback, and malformed input. `pnpm test` and `pnpm typecheck` pass. No unresolved issues.
- #15: Added `detectMakefile` in `src/detect/makefile.ts` and re-exported it with `MakefileReport`, source, and target-name types. It returns ordered unique target names and `make` commands for test/check/build/install, while skipping `.PHONY`, assignments (including modifier forms), `%` pattern rules, comments, and tab-prefixed recipes; absent and empty Makefiles remain distinct. Added fixture-backed public tests for the public export, target recognition, absent/empty files, and each parser exclusion. `pnpm test` and `pnpm typecheck` pass. No unresolved issues.
- #16: Added `detectGitHubActions` in `src/detect/github-actions.ts` and re-exported it with its report types and `GitHubActionsYamlSyntaxError` from `src/index.ts`. It scans `.github/workflows` YAML files in order, extracts workflow names, triggers, ordered job `run` steps, literal multi-line commands, and a likely test command/workflow for `push` or `pull_request` workflows. Steps using services, secrets, or Docker are marked with unavailable requirements. A strict targeted YAML subset parser rejects unsupported syntax such as folded block scalars without adding a runtime dependency. Added fixture-backed public tests in `src/detect/github-actions.test.ts` for absence, multiple workflows, block commands, test-workflow selection, unavailable requirements, and unsupported YAML. `pnpm test`, `pnpm typecheck`, and the targeted Vitest run pass. No unresolved issues.
- #17: Added `detectTurbo` in `src/detect/turbo.ts` and re-exported it with `TurboFileName`, `TurboReport`, and `TurboTaskReport` from `src/index.ts`. A first traversal skipped a configured `build` task itself; the test for a build task depending on `^build` exposed that and the traversal now checks task dependencies before treating a dependency named build as terminal. Added fixture-backed public tests for the task graph, transitive build detection, environment declarations, legacy key, and malformed JSON. `pnpm test`, `pnpm typecheck`, and the targeted Vitest run pass. No unresolved issues.
